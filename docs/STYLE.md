# Clarry 视觉与语气风格

日系幻想 RPG。参考坐标：塞尔达（明亮的自然与金色）、百万亚瑟王（华丽卡面、厚描边、金黑对比）、
魔界战记（高反差、夸张表情、紫红黑）。

**世界观不预设。** 这几部作品只提供「质感」，不提供「内容」。Clarry 的世界、人物、势力
全部由 Agent 从空白处长出来。

## 一、四条共同点（从这里提取，不从任何一部照搬）

1. **厚描边 + 高饱和**：轮廓是明确的线，不是渐变糊边；颜色敢满。
2. **卡片与卷轴式构图**：信息装在有边框的容器里，边框本身就是装饰。
3. **幻想装饰纹样**：藤蔓、魔纹、宝石、羽毛笔、羊皮纸边缘。装饰在留白处，不压正文。
4. **光与暗的对话**：暗底托亮物，或者亮底压暗字，中间不糊。

## 二、配色令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--cl-night` | `#1A1E3A` | 主背景（暗夜蓝） |
| `--cl-violet` | `#2B1B4A` | 次级背景、卡片底（深紫罗兰） |
| `--cl-ink` | `#0D0F1F` | 最深，用于压边与遮挡 |
| `--cl-gold` | `#D4AF37` | 主强调、边框、标题（黄金） |
| `--cl-gold-dim` | `#A8894A` | 次级金线、分隔 |
| `--cl-mana` | `#4FD1C5` | 魔法/交互态（青） |
| `--cl-crimson` | `#C1272D` | 危险、敌意、骰子（绯红） |
| `--cl-ivory` | `#F5EBDC` | 正文（象牙） |
| `--cl-parchment` | `#E8DCC0` | 卷轴底（羊皮纸） |

配对规则：正文永远 `--cl-ivory` on `--cl-night`/`--cl-violet`；金色只做强调，不做大面积填充。

## 三、字体

- 标题：衬线（日系幻想感），字重偏重，字距略松。
- 正文：无衬线，行高 1.6 以上，中文不缺字。
- 数字与骰点：等宽。

## 四、形状与边框

- 卡片圆角 4–6px，不要大圆角（那是移动端现代风，不是 RPG）。
- 边框双层：外细金线 + 内 1px 暗描边，中间留 4px 空白。
- 分栏用竖线加菱形端头，不用纯色块。

## 五、人物立绘

| 阶段 | 手段 | 产出 |
| --- | --- | --- |
| 一 | 纯文本 | 人物卡（role/voice/traits） |
| 二 | ichiwatashi | 像素立绘，按世代参考分布校准 |
| 三 | ichiwatashi | 表情差分（喜/怒/哀/惊/困惑，至少 5 张） |
| 四 | lineweight | 插画级线稿，用于卡片大图 |
| 五 | Live2D | 绑定 + 呼吸/眨眼/说话 |
| 六 | Blender | 3D 角色、有机形、动画与骨骼（可选） |
| 七 | Rhino（NURBS） | 硬表面：吧台、杯具、家具、门框 |
| 八 | Photoshop | 贴图精修、立绘后期、色彩统一 |

风格化（lineweight 与 ichiwatashi）永远排在最后：它是可重复的工序，而建模不是。先把形体做对，再决定用什么笔触它。

像素风优先。表情差分先做，动作后做。

## 六、舞台

- 场景是「画卷」而不是「3D 场景」：横向展开，前景人物，中景建筑，远景天光。
- 时间变化用调色而非重画：黄昏加暖，夜加蓝，雨加灰。
- HUD 元素（角色名、状态）用羊皮纸小标签，压在人物脚下。

## 七、语气

这不是 UI 风格，是文本风格，但同属「日系幻想 RPG」：

- 叙述克制，多用名词与动作，少用形容词堆叠。
- 角色对话有个人的口癖与节奏，写在 `sheet.voice` 里。
- 旁白与角色台词要有视觉区分（斜体 / 不同缩进 / 引号层级）。

## 八、禁止

- 不用 emoji 当图标。
- 不用纯黑白灰的极简风。
- 不用圆润到没有性格的按钮。
- 不把参考作品的专有名词、角色、地名搬进来。

## 九、语言

观众看到的字一律中文，代码内部一律英文。这条界线要守死，中间不留灰区。

**中文的部分**（写给人看的，也包括写给观众看的叙述）：

- 舞台界面的一切文字：按钮、标签、状态、提示。
- 回合日志与结算备注，例如 `第 3 轮结算（6 条行动）`、`鲍勃 看穿了 卡萝尔（触及 90）`。
- 行动的六个名字统一从 `OrderKindText` 取，界面与日志不许各叫各的。
- 测试脚本的输出：`通过`、`失败`、`全部检查通过`。
- 存档里的台词与旁白，脚本驱动的兜底台词也算。
- 调用方能读到的报错，例如 `还没有开始的回合，先开一轮`。

**英文的部分**：

- 标识符、类名、方法名、CSS 类名、API 字段名、路由。
- 枚举值（`speak` / `act` / `probe`）与 JSON 键。
- 给模型看的提示词（`DriverPrompt`）：模型对英文指令的遵循更稳，而这些文本从不显示给观众。
- 代码注释：与 API 名、术语混排时英文更省字。

不许中英并置。`说话 speak` 这种写法两边都不讨好——中文读者被英文剁断，英文读者也没拿到完整信息。要么写成中文，要么整句英文。
